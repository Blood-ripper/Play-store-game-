# Architecture

Farm Rush is a Flutter app with an embedded Flame game and a Firebase backend.
It is built so every system works **offline/local first** and transparently
upgrades to the cloud when `FIREBASE_ENABLED=true`.

```
            ┌─────────────────────────── UI (Widgets) ───────────────────────────┐
            │ splash · login · home(hub) · game · shop · leaderboard · profile    │
            └───────────────┬───────────────────────────────┬─────────────────────┘
                            │ watch / read (Provider)        │ embeds
                            ▼                                 ▼
                    ┌───────────────┐                 ┌───────────────┐
                    │   AppState    │  (ChangeNotifier)│   FarmGame    │ (Flame)
                    │ single source │◀────recordRun────│  Tractor+Crop │
                    │   of truth    │                 └───────────────┘
                    └──┬────┬────┬──┘
          ┌────────────┘    │    └───────────────┐
          ▼                 ▼                    ▼
   AuthService      PlayerRepository      LeaderboardService      IapService
   (Firebase Auth   (Firestore + local    (Firestore + local      (Play Billing
    / local guest)   SharedPreferences)    seed)                   / sandbox)
          │                 │                    │                    │
          └─────────────────┴──────── Firebase ──┴────────────────────┘
                                         │
                              Cloud Functions (verifyPurchase,
                              onScoreWrite, getLeaderboard)
```

## Key decisions

**`AppState` as the single source of truth.** All currency, inventory,
equipped vehicle/frame, and derived state (owned glows → unlocked frames, coin
multiplier) live here. The UI only reads from it via `provider`. This keeps the
glow/frame logic in one place: `ownedGlows` is computed from owned premium
content, and the best frame is auto-equipped.

**Local-first services.** Each service checks `AppConfig.firebaseEnabled`. In
local mode it uses `SharedPreferences` (profiles, leaderboard seed) so the game
is fully playable and demoable with zero backend. In cloud mode the same API
hits Firestore. The UI never changes.

**Data-driven catalogs.** The 100 vehicles and 100 items are generated by
`tool/generate_catalog.py` into both Dart (shipped in-app, offline) and JSON
(seeded to Firestore for live tuning). Prices, tiers, stats, and the 2+2 free
unlocks are all data — no code changes to rebalance.

**Trust boundary for money.** Clients never grant their own gems/coins/VIP.
`IapService` runs the Play Billing flow; the Cloud Function `verifyPurchase`
validates the purchase token with Google and writes the grant with the Admin
SDK (which bypasses security rules). `firestore.rules` blocks clients from
editing `vip` and caps leaderboard scores; `onScoreWrite` clamps them.

**The glow/frame system.** Every premium catalog entry carries a `Glow`
(silver/gold/rainbow/legendary). Owning one unlocks the matching
`PlayerFrame`. `PlayerAvatar` renders a plain ring for free players and an
animated, pulsing, rotating glow for premium/VIP players — and because the
leaderboard stores each player's `frameId`, that glow is visible to everyone.

## Extending with more game modes

Each reference screenshot maps to a Flame "mini-game" that reuses the same
pattern as `FarmGame`: a `FlameGame` subclass with components + a results
callback into `AppState.recordRun`. Add a new file under `lib/game/`, a card in
`_FarmHub`, and route to a new `GameScreen`-style host. See
[`ROADMAP.md`](ROADMAP.md).
